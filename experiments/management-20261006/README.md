# Experiment decisions, 6 October 2026

## Executive summary

All six experiments started at the same source commit. The differential checker
and the Python-only liquidity-gap reducer are integrated into `codex/develop`.
The native C module remains experimental. The indexed book was initially selected,
then removed from the active build after the user questioned its slower lifecycle
result. Other unselected implementations stay in their experimental branches. Their reports are
preserved here. The indexed book is correct, but its measured performance was
mixed and did not meet the original 5% target on both primary workloads.
The historical results and recommendations have not been rewritten.

## Ответы и решение

1. **Heap-очередь.** На двух из трёх нагрузок полный запуск медленнее на 6,44%
   и 7,78%; momentum быстрее на 8,10%, но результаты перекрываются. Сама очередь
   быстрее в микротесте. Общего ускорения симуляции нет. Только отчёт перенесён.
2. **Индексы стакана.** Выигрыш не везде: lifecycle медленнее на 12,91%, STP-old
   примерно на 0,98%. Churn быстрее на 4,16%, deep-book — на 2,46%, ниже исходного
   порога 5%. Дополнительная память структуры стакана +58,4% (+2,21 MiB в тесте
   10 000 заявок / 1 000 уровней); это не рост памяти всего контейнера на 58%.
   После уточнения пользователя реализация убрана из активной сборки; сохранён
   только отчёт. Исторический вердикт `do_not_adopt` остаётся актуальным.
   `t3-cancelmodify-lifecycle` — смешанный поток выставления заявок, частичных
   исполнений, проходов по уровням, отмен и замен с проверкой price/time priority.
   Медиана полного запуска выросла с 10,586 до 11,953 секунды. Корректность
   сохранена; речь о скорости, а не неправильных сделках. Три пары локальных
   измерений не устанавливают универсальное замедление на любых рынках.
3. **Параллельный batch.** Homog-8 быстрее на 15,65% по медиане; остальные пять
   batch медленнее. В реализации уже есть ограниченный переиспользуемый пул
   внутри batch и приватные каталоги рынков. Следующие отдельные гипотезы:
   выбирать serial/2 по прогнозируемой длительности и памяти; амортизировать
   создание пула между несколькими batch в долгоживущем процессе; отправлять
   долгие независимые рынки раньше; подтвердить выигрыш на Linux без Rosetta.
   Проверять обе трассы, сброс RNG/ID, перемешивание рынков и отказы работников.
   Четыре работника не допущены: ранний BrokenProcessPool не объяснён.
   Только отчёт перенесён; эти идеи пока не реализованы и не измерены.
4. **SimulationContext.** Каждый рынок получает собственные RNG, счётчики
   order/message ID, Kernel, очередь, агентов, сборщик трасс и жизненный цикл.
   Можно безопасно чередовать шаги независимых рынков, не изменяя состояние
   вызывающего кода. 504 запуска совместимы, неоднородная пара тоже проверена.
   Это основа изоляции, а не доказательство общего ускорения или произвольной
   многопоточной безопасности. Короткий сценарий замедлен на 6,42%; патч широкий.
   Только отчёт перенесён, реализация остаётся отдельным возможным шагом.
5. **Нативный участок.** На основном oracle время выросло на 2,84%; критерий
   не пройден. На churn C быстрее baseline на 22,01%, простой Python control —
   на 16,48%. Преимущество C над Python неустойчиво: C быстрее в одной из трёх
   пар. Нативную реализацию не интегрируем. По последующему решению пользователя
   Python control включён в develop: [отдельный отчёт](../python-control-integration/README.md).
   Прошли 373 локальных теста и повторная проверка сохранённых обеих трасс/full
   developer gates на s001/oracle/churn. Новые Docker-запуски, сборку образа и
   regression65 не выполняли по уточнению пользователя.
6. **Сравнительный контроль.** Интегрированы runner, Make target, тесты и
   обязательный цикл build → сравнение обеих трасс / developer gates → отчёт.
   В эксперименте прошли 40 реальных запусков, 52 точных сравнения и 22
   отрицательных случая (19 новых + 3 прежних). Сам двигатель не меняется.

## Проверки и происхождение

База: `a5dbe466f038389e96f44d6f71f1258e2eddcbb5`. Каждая папка содержит исходные
`README.md`, `result.json` и `manager-validation.json`; heap/native также
содержат `REPORT.md`. Исходные ветки, commits, команды и внешние пути больших
артефактов сохранены в результатах. Команды отчётов для гипотез 1, 2, 3, 4, 5
воспроизводятся в соответствующих экспериментальных ветках, где остался код.

Все измерения — локальные Mac ARM64 / linux/amd64 Rosetta, `rankable=false`,
обычно три пары без профилировщика. Полные developer gates запускались на
выбранных релевантных units; это не допуск всех 71 units по runtime. Public
regression65 прошёл для реализаций 1–5; runner #6 переиспользовал проверенное
доказательство #3, сохранив атрибуцию. Для batch нужен явно отмеченный serial
contract-only control: исходный baseline пишет запрещённый корневой profile.json.
Scorer, reference traces, cards и допуски не изменялись.

Проверки записаны в `integration-validation.json`. До пересмотра решения новый
Make target успешно запускал baseline и book image на s001, а standard regression
checks повторно проверили 65 сохранённых результатов того же book image.
Это сохранённое доказательство прежнего сочетания #2 + #6, не утверждение о
наличии индексов в итоговой сборке. После пересмотра индексы отключены,
сравнительный контроль #6 остаётся включён. Позднее добавлен только Python control
из №5; оригинальные очередь, стакан и порядок сообщений сохранены.
