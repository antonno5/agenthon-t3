# Kernel message ledger experiment

## Executive summary

This directory contains the improvement, the commands that apply it, targeted tests,
measurements and a decision. The default run uses local Python and takes seconds;
Docker verification is a separate optional step. The current decision is to keep the
change for lower ledger processing time and memory. Whole-simulation speed remains unproven.

## Применён ли патч

В рабочем baseline новый патч уже выбран в `baselines/Dockerfile`, а обработка нового
формата добавлена в `baselines/abides_fork/trace.py`. При сборке Dockerfile действительно
применяет патч к закреплённому ABIDES через `git apply`. В предыдущем контейнерном
эксперименте это применение и совпадение трасс проверены.

В локальном эксперименте команда также **реально применяет патчи**: создаёт две
отдельные копии pinned Kernel и адаптера, применяет before/after изменения и проверяет
результат по SHA-256. Затем тестирует именно эти копии. Применённые файлы находятся
в `runs/<id>/applied/before/` и `runs/<id>/applied/after/`; пути, хеши и совпадение after
с baseline записаны в `application.json`. Системный пакет ABIDES не устанавливается.

## Улучшение

Раньше ядро сохраняло словари отправлений и отдельную таблицу `(message_id, recipient) → seq`.
После симуляции адаптер соединял структуры, исключал недоставленные сообщения и сортировал.

Теперь до доставки хранится компактный снимок метаданных отправки. На окончательной
доставке в журнал добавляется кортеж; `seq` равен позиции строки. Каждый получатель
рассылки имеет свою запись, причинность фиксируется при отправке, недоставленные
сообщения исключаются. При requeue сохраняется прежняя семантика планового `t_recv_ns`;
фактический порядок обработки отражает `seq`.

| Файл | Роль |
|---|---|
| `kernel_message_ledger.patch` | Новый патч к исходному pinned Kernel. |
| `legacy_kernel_message_ledger.patch` | Прежний патч для before. |
| `adapter.patch` | Изменение адаптера: чтение компактного формата без фильтрации и сортировки. |
| `experiment.json` | Нагрузка и критерии принятия компонента. |
| `run.py`, `local.py` | Полный цикл применения, проверки и замеров. |
| `microbenchmark.py` | Отдельные замеры времени и Python heap. |
| `RESULTS.ru.md` | Краткая сводка завершённого прогона и вердикт. |

## Полный цикл одной командой

Из корня репозитория:

```sh
make experiment-ledger
```

Из этого каталога ту же команду запускает `../../.venv/bin/python run.py`.
По умолчанию используется локальная `.venv`, Docker не вызывается.

1. Получаем исходный Kernel закреплённого ABIDES и проверяем SHA-256. Берём из локального
   кеша или прежнего эксперимента; на чистом checkout однократно скачивается один файл
   по точному commit. Свою копию можно указать через `--kernel-source /path/kernel.py`.
2. Сохраняем исходники, патчи, версии, нагрузку и критерии. Создаём before/after копии
   и применяем патчи с `git apply --check` и `git apply`; результат фиксируем в `application.json`.
3. Запускаем только два целевых файла: `tests/test_delivery_ledger.py` и
   `tests/integration/test_delivery_ledger_kernel.py`. Они используют применённые
   Kernel и after-адаптер. Пропуски и ошибки блокируют принятие.
4. Измеряем сборку таблицы на 90 000 доставках: разогрев, три повтора каждого варианта,
   чередующийся порядок. В before есть также 900 недоставленных отправлений.
5. Отдельно измеряем память и проверяем равенство таблиц и байтов Parquet.
6. Записываем краткое описание, вердикт с причиной, логи и подробный отчёт.

Kernel-тесты исполняют реальные методы класса Kernel с тестовыми агентами и сообщениями.
Проверяют порядок и равное время, requeue, wakeup, рассылку, MessageBatch, causal_parent,
мутацию payload, недоставленные сообщения, stop_time и pause/resume. В микробенчмарке
неиспользуемый парсер логов ABIDES заменён функцией, которая падает при вызове;
сама функция извлечения сообщений загружается из применённого файла адаптера.

## Замеры и критерий решения

Время охватывает только `extract_message_trace`; создание fixture и запись Parquet
исключены. `tracemalloc` выключен в скоростных замерах. Память измеряется отдельным
прогоном: входные структуры плюс сборка таблицы; это Python heap, а не RSS контейнера.
Версии Python, pandas, NumPy и PyArrow записываются в результат. Замеры разных окружений
не сравниваем как один и тот же benchmark.

Цель этого эксперимента — уменьшить расходы журнала. Поэтому `experiment.json`
принимает изменение при снижении времени компонента и пика Python heap хотя бы на 10%
каждого, пройденных целевых тестах и точном Parquet. Это локальный практический порог,
без оценки статистической значимости. Вердикт **«делаем»** относится к этому компоненту;
из него не следует ускорение всего контейнера. Скрипт не откатывает baseline автоматически.

## История в этом каталоге

Каждый запуск создаёт `runs/<UTC>-<id>/` и сохраняет прежние результаты.

| Артефакт | Содержание |
|---|---|
| `application.json`, `apply-before.log`, `apply-after.log` | Применение патчей, пути и хеши получившегося кода. |
| `applied/before/`, `applied/after/` | Реальные файлы до и после улучшения, использованные в проверках. |
| `tests.log`, `tests.xml` | Лог целевых тестов и машинный результат. |
| `microbenchmark/`, `microbenchmark.log` | Сырые замеры, обе Parquet-таблицы и хеши. |
| `REPORT.ru.md`, `summary.csv`, `summary.json` | Результаты, версии и время стадий эксперимента. |
| `CHANGE.ru.md`, `decision.json` | Краткое описание и итоговое «делаем / не делаем» с причиной. |
| `metadata.json`, `snapshot/`, `changes.patch` | Параметры, commit, снимок кода и изменения относительно HEAD. |
| `source_changes.json` | Изменения исходников относительно предыдущего локального запуска. |

`latest.json` указывает последний успешно завершённый локальный эксперимент.
Кеш и большие артефакты исключены из Git; исходники эксперимента и краткая сводка остаются.

## Контейнерная проверка перед приёмкой

Отдельный режим сохраняет прежний цикл сборки двух образов, сравнения их времени,
профилей компонентов и developer gates на одном маленьком задании:

```sh
make experiment-ledger EXPERIMENT_ARGS='--mode container'
```

В этом режиме: работающий `colima-agenthon`, кандидат `my-simulator:local`, только
`t3-s001-price-time-priority`. Полный набор заданий и весь pytest suite не запускаются.
История контейнерных прогонов остаётся в `out/experiments/`. Его прежний критерий 5%
контейнерного времени оценивает общее ускорение отдельно от локального решения по компоненту.

Согласованная одиночная проверка уже собранного кандидата:

```sh
DOCKER_CONTEXT=colima-agenthon make unit \
  UNIT=t3-s001-price-time-priority \
  IMAGE=my-simulator:local \
  RESULTS=out/quick-check
```
