# Kernel message ledger experiment

## Executive summary

The current kernel records compact message rows when they are delivered. This experiment
compares it with the previous send ledger while keeping the rest of the simulator fixed.
It measures table extraction, Python memory and complete container time, checks both
reference traces, and records a keep or reject decision. A faster extraction step does
not by itself prove that the whole simulation is faster.

## Изменение

Раньше ядро сохраняло словарь при отправке и отдельный `(message_id, recipient) → seq`
при доставке. Адаптер соединял эти структуры, исключал недоставленные сообщения,
сортировал доставки и строил таблицу.

Теперь до доставки хранится компактный снимок метаданных отправки. На окончательной
доставке строка добавляется в журнал; `seq` равен её позиции. Отдельная таблица seq
и последующая сортировка исключены. Для каждого получателя рассылки сохраняется
отдельная запись. `causal_parent` фиксируется при отправке; недоставленные сообщения
не попадают в результат. `t_recv_ns` сохраняет прежнее значение плановой доставки,
в том числе при requeue; фактический порядок обработки задаёт `seq`.

Изменения уже реализованы в `baselines/patches/kernel_message_ledger.patch` и
`baselines/abides_fork/trace.py`. Этот эксперимент оформляет и измеряет их.

## Одна команда

```sh
make experiment-ledger
```

По умолчанию: Docker `colima-agenthon`, кандидат `my-simulator:local`, три измеряемых
повтора и один разогрев. Все симуляции используют только `t3-s001-price-time-priority`.
Ограничения 30 секунд и 3 минуты не вводятся. Полный набор публичных заданий и весь
pytest suite не запускаются.

Команда выполняет:

1. Снимок текущего кода и два входа сборки с одинаковым адаптером и сборщиком событий.
2. Сборку before из закреплённого прежнего патча и after из текущего патча. Проверяет,
   что различается только `patches/kernel_message_ledger.patch`.
3. Целевые тесты `test_delivery_ledger.py` и `test_delivery_ledger_kernel.py`. Для вторых
   получает исходный pinned Kernel из собранного образа обратным применением патча
   и проверяет SHA-256; тесты ничего не скачивают.
4. Синтетический замер 90 000 доставок и 900 недоставленных отправлений: отдельно
   сборка таблицы, пик Python heap и побайтовое совпадение Parquet.
5. Чередующиеся before/after запуски одного публичного unit, полные developer gates,
   хеши обеих трасс, отдельные диагностические профили компонентов.
6. Согласованную `make unit` проверку кандидата и запись отчёта с вердиктом.

Сборка before полноценная через тот же Dockerfile: overlay адаптера не может
заменить патч установленного ядра. Прежний патч зафиксирован в
`legacy_kernel_message_ledger.patch` из исходной Git-версии; текущий код вне
эксперимента не переключается на него. Кандидат остаётся в `my-simulator:local`.

## Что измеряется

| Измерение | Граница |
|---|---|
| Сборка таблицы | Только `extract_message_trace`; создание fixture и Parquet исключены; tracemalloc выключен. |
| Пик Python heap | Создание исходных структур плюс сборка таблицы; отдельный tracemalloc запуск; это не RSS контейнера. |
| Время контейнера | Docker StartedAt → FinishedAt, включая импорты и запись результатов. |
| Компоненты | Конфигурация, очередь, matching, агенты, ядро, финализация сообщений, сериализация и прочие стадии; отдельные профильные запуски. |

Синтетический тест использует тот же Python/pandas/NumPy/Parquet стек в образе,
что и симуляция. Он содержит порядок доставки, отличный от отправки, nullable int64
выше `2**53`, wakeup и разные получатели. Реальные kernel-тесты дополнительно проверяют
requeue, MessageBatch, причинность, мутацию payload, stop_time и pause/resume.

## Результаты и вердикт

История: `out/experiments/<UTC>-kernel_message_ledger-<id>/`.

| Файл | Содержание |
|---|---|
| `CHANGE.ru.md`, `decision.json` | Описание и «делаем / не делаем» с причиной. |
| `REPORT.ru.md`, `summary.csv`, `summary.json` | Контейнер, компоненты, проверки трасс и синтетические результаты. |
| `metadata.json`, `snapshot/`, `changes.patch` | Код, версии, окружение, параметры, image ID и diff. |
| `build-context/`, `build-inputs.json`, `build-*.log` | Оба входа сборки, их хеши и логи; проверка изоляции изменения. |
| `targeted-tests.log`, `quick-check.log` | Целевые тесты и согласованная проверка unit. |
| `microbenchmark/`, `microbenchmark.log` | Сырые замеры, профиль памяти и оба синтетических Parquet. |
| `before/`, `after/`, `runs.jsonl` | Трассы, профили и логи каждого реального запуска. |
| `source_changes.json` | Изменения исходников относительно предыдущего эксперимента при повторном запуске. |

Автоматический вердикт следует общему README: при точных трассах и пройденных проверках
принимаем ускорение контейнера не менее 5%. Улучшение только синтетической сборки
не удовлетворяет этому критерию; его всё равно показываем в отчёте. Такой вердикт
не означает автоматического отката уже существующего кода.

Для записи осознанного решения ради памяти или другой цели:

```sh
make experiment-ledger EXPERIMENT_ARGS='--verdict yes --reason "Краткая причина принятия"'
```

При ошибках, расхождении трасс или незавершённом запуске явное решение не принимается.
Следующий запуск создаёт отдельный каталог, показывает изменения кода и сравнение
с предыдущим `kernel_message_ledger` экспериментом. Маленький unit не доказывает
ускорение больших сценариев или официального Final.
