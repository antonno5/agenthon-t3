Изменения и ограничения вариантов:

- **Упростить финализацию трасс**: Убраны промежуточная коллекция строк и хеш-дедупликация котировок; остаётся прежняя глобальная сортировка lifecycle-событий. Журнал формируется прямым слиянием колонок и котировок.
- **Сортировка событий по группам времени**: Lifecycle-события собираются хронологически и сортируются внутри групп одинакового времени; для немонотонного времени предусмотрен общий путь. Стабильный порядок при совпадении ключей сохранён.
- **Пул стабильных уровней стакана**: Уровни хранятся в стабильном пуле, ценовой индекс перемещает целочисленные handles. Сохранены bisect/lower_bound, быстрый доступ к вершине, добавление в хвост и смещение начала.
- **Компактный реестр заявок агента**: Реестр заявок агента использует компактные slots, связи порядка вставки и хеш-индекс ID → slot вместо node-based map. Снимки и порядок cancel-all сохранены.
- **Индексированная FIFO заявок уровня**: Очередь уровня хранится в slots со связями prev/next. Для короткой очереди сохраняется линейный поиск, при размере 8 подключается индекс по ID. Порог зафиксирован до измерений. Хранилище может сохранять исторический максимум до удаления уровня; это ограничивает привлекательность варианта.
- **Однократное выделение строковых буферов Arrow**: Для строковых колонок заранее вычисляются offsets и размер данных; буфер выделяется один раз и заполняется напрямую. Версия Arrow, схема, nullable-свойства и настройки Parquet сохранены.
- **Четырёхарная очередь событий**: Бинарная очередь событий заменена на четырёхарную кучу в непрерывном массиве. Comparator и последовательность доставки сообщений сохранены.
- **Кольцевая история MomentumTrader**: История MomentumTrader хранится в растущем до lookback+1 кольцевом массиве. Порядок расчётов, порог старта и случайные решения сохранены. Проверки большого lookback подтверждают корректность, но не являются замерами производительности.

У каждого эксперимента выбран набор сценариев, где меняемый компонент задействован: lifecycle-трассы — глубокий стакан, отмены и partial fills; структуры заявок — churn, cancel/modify, STP и atomicity; Arrow — объёмные журналы, короткий запуск и heterogeneous batch; очередь событий — heavy flow, momentum и разные распределения задержек; история MomentumTrader — momentum, shock и volatility clustering. Полный прогон 71 задания не выполнялся.

Выбор гипотез учитывал предыдущие результаты: ускорение отдельного поиска не гарантировало ускорения полного стакана, компактные Python-события ранее проигрывали базе, streaming SHA и параллельные batch-рынки давали смешанные либо отрицательные результаты. Поэтому текущие варианты изолированы, существующий ценовой индекс сохранён, старые времена используются только как мотивация. Контрольные времена в таблице получены заново для каждого варианта.

Все измерения выполнены последовательно в Docker context `colima-agenthon`, `linux/amd64`, 4 CPU, 16 GiB RAM, 16 GiB memory+swap, без сети. Версии: Python 3.11.17, Arrow 15.0.2. В каждом запуске подтверждено использование native-ядра, пройдены общие developer gates, проверены bytes/schema/ordered values обоих журналов и SHA256. Независимый аудит проверил исходники, медианы и отсутствие пересечения интервалов контейнеров.

**Ограничение:** локальный Mac ARM64 с эмуляцией amd64; результаты `rankable:false`. Пять пар дают ориентир для последующих решений, но небольшие различия в пределах нескольких процентов нельзя считать устойчивым эффектом. При смешанных результатах нельзя заявлять универсальное ускорение.
