# Component experiments for Track 3

## Executive summary

The simulator now captures events in typed buffers and records time spent in its
components. Check correctness with one requested public unit. Use `make experiment`
to compare changes and save a description, decision, source snapshot, logs and timings.
The default experiment uses the same single unit. Local timings are not official scores.

## Проверка корректности

Из корня репозитория:

```sh
DOCKER_CONTEXT=colima-agenthon make unit \
  UNIT=t3-s001-price-time-priority \
  IMAGE=my-simulator:local \
  RESULTS=out/quick-check
```

Это единственная команда проверки, которую используем для текущей работы.
Она запускает выбранное задание и полный developer verifier для его результата.
Все задания репозитория автоматически не запускаются.

## Эксперимент одной командой

```sh
make experiment
```

Команда пересобирает `my-simulator:local` через `baselines/Dockerfile`, сравнивает
`legacy` и `buffered` на `t3-s001-price-time-priority` и сохраняет историю.
Для каждого режима: один разогрев, три измеряемых повтора и отдельный профиль
компонентов. Порядок режимов чередуется. Профильные запуски не входят в сравнение
скорости. Ограничений 30 секунд или 3 минуты нет. При `Ctrl+C` активный контейнер
удаляется, завершённые результаты остаются в журнале.

Используется работающий Docker-контекст `colima-agenthon`; глобальный контекст
не меняется, VM не запускается. Другой контекст задаётся через `DOCKER_CONTEXT`.
Один маленький unit подходит для проверки правил и работоспособности измерений;
по нему нельзя оценить выигрыш на больших сценариях.

## Описание и вердикт

При следующем изменении:

```sh
make experiment EXPERIMENT_ARGS='--name next-change --description "Что изменили и зачем"'
```

Каждый эксперимент содержит краткое описание и вердикт **«делаем / не делаем»**
с причиной в `CHANGE.ru.md`, `decision.json` и основном отчёте.
Автоматическое правило: эксперимент завершён, все gates пройдены, обе трассы
побайтово совпадают с эталоном и стабильны между повторами; сумма медиан
контейнерного времени снизилась хотя бы на 5%. Требуется не менее трёх
измеряемых повторов каждого сравниваемого задания. Это локальное правило,
без оценки статистической значимости и без вывода об официальном рейтинге.

При одинаковых наборе, режимах, повторах и окружении сравнивается `buffered`
предыдущего и текущего экспериментов. Иначе используется сравнение `legacy`
и `buffered` текущего эксперимента. Основание записывается в решении.

Для изменения ради измеримости или другой цели можно записать решение явно:

```sh
make experiment EXPERIMENT_ARGS='--name observability --description "Добавлены метрики" --verdict yes --reason "Принимаем ради измеримости компонентов"'
```

Явное решение требует причины. Незавершённый эксперимент, отказ gates или
расхождение трасс не позволяют принять изменение даже при `--verdict yes`.

Для выбора другого задания нужен явный параметр `--units <unit>`;
предыдущий результат можно указать через `--previous /absolute/path/to/summary.json`.
Без него используется последний завершённый эксперимент того же набора.

## История изменений и запусков

Каждый запуск создаёт новый каталог `out/experiments/<UTC>-<имя>-<id>/`.

| Файл или каталог | Содержание |
|---|---|
| `CHANGE.ru.md`, `decision.json` | Краткое описание и вердикт с причиной. |
| `REPORT.ru.md` | Время запусков, сравнение режимов, компоненты и сравнение с предыдущим экспериментом. |
| `summary.csv`, `summary.json` | Медианы измеряемых повторов и результаты проверок. |
| `metadata.json` | Параметры, commit, Docker, image ID, версии и хеши исходников. |
| `changes.patch`, `snapshot/` | Diff относительно HEAD и копии исходников, включая новые файлы. |
| `source_changes.json` | Изменённые исходники относительно предыдущего эксперимента. |
| `build.log`, `runs.jsonl` | Лог сборки и журнал завершённых запусков. |
| `runs/` | Логи контейнеров, обе трассы, статистика и профиль каждого запуска. |

Старые результаты не перезаписываются. После каждого запуска обновляется отчёт;
незавершённые эксперименты не становятся базой следующего сравнения.

## Время компонентов

`container_sec` берётся из Docker `StartedAt` и `FinishedAt`: включает импорты Python
и запись результата, исключает создание и удаление контейнера. `host_launch_sec`
дополнительно содержит расходы Docker CLI. `container_other_sec` показывает время
вне измеренной работы адаптера.

`profile.json` содержит вход, конфигурацию, финализацию событий и сообщений,
запись Parquet, хеширование, метаданные. С `--profile-components` симуляция разделяется
на очередь, matching, агентов, exchange, latency, oracle, захват событий и остаток
ядра. Вложенные вызовы вычитаются из времени родителя. Таймеры добавляют расходы,
поэтому этот профиль используется для объяснения времени, а не оценки ускорения.

`events.json.wall_clock_sec` учитывает адаптер до завершения первой записи метаданных;
`simulation_wall_clock_sec` отдельно хранит время `abides.run`. Импорты и финальные
записи маленьких JSON учитываются внешним временем контейнера. Для batch складываются
профили подсценариев и показывается `batch_other`.

`--trace-mode verify` сравнивает сборщики на одном запуске с сохранением исходных логов.
Для разработки только адаптера доступны `--base-image <image>` (overlay без пересборки
патчей ядра) и `--skip-build`; выбранный способ фиксируется в метаданных.
